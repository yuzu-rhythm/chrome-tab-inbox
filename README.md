# まだやっていない

「まだやっていない」は、新しく開いたタブを灰色の `tmp` で受け取り、Raycast風のキーボードパレットから名前付きグループへ振り分ける、自分用のChrome拡張機能です。Optionsで `研究`、`買うもの`、`今週読む` などを最大9件プリセットでき、現在開いている未登録グループもOverviewにすべて表示できます。同じウィンドウ内ではグループ名を一意に保ち、重複した同名グループはタブを閉じずに1つへ統合します。オレンジ色の `まだやっていない` はReading Listと連携する既定Inboxとして残します。

v1.3はManifest V3、Chrome 120以上、ビルド不要のHTML/CSS/JavaScriptでできています。Node/npmは拡張機能のインストールや実行に必要ありません。`package.json` と `tests/` は、Nodeがある環境で任意に依存なしテストを実行するためだけのものです。

## インストール（Mac Chrome）

1. このフォルダーをダウンロードまたは配置します。
2. Chromeで `chrome://extensions` を開きます。
3. 右上の「デベロッパーモード」をオンにします。
4. 「パッケージ化されていない拡張機能を読み込む」を押します。
5. このフォルダー（`manifest.json` が直接入っているフォルダー）を選びます。
6. 拡張機能一覧に「まだやっていない」が表示されたら完了です。

拡張機能のコード変更後は、`chrome://extensions` でこの拡張機能の「再読み込み」を押してください。再読み込みや拡張機能の更新で、保存済みの `bridgeEnabledAt` はリセットされません。

## ショートカット

Chromeのglobal commandには、最初から任意のOptionキーを提案できない制約があります。そのため安全な初期キーを設定し、Chromeの設定画面でMac用キーへ変更します。

1. `chrome://extensions/shortcuts` を開きます。
2. 「未処理専用ウィンドウを開く」または `open-unfinished` を探します。
3. global（グローバル）の欄に **Option + T** を設定します。Chromeの表示上はMacのOptionが `Alt` と表示される場合があります。
4. 「現在のタブを未処理専用ウィンドウへ送る」または `add-to-unfinished` を探します。
5. **Option + Shift + T** を設定します（表示が `Alt + Shift + T` になる場合があります）。
6. 「開くグループを選ぶ」または `open-group-picker` のglobal欄に **Option + G** を設定します。
7. 「現在のタブを入れるグループを選ぶ」または `choose-group-for-current` に **Option + Shift + G** を設定します。

Manifest上の初期値は、未処理を開くglobal commandが `Ctrl + Shift + 5`、未処理へ送るChrome内commandがMacでは `Option + Shift + T`、任意グループを開くglobal commandが `Ctrl + Shift + 7`、任意グループへ送るChrome内commandがMacでは `Option + Shift + G` です。macOSではManifestの `Ctrl` が `Command` として登録されるため、初期状態ではそれぞれ `Command + Shift + 5` と `Command + Shift + 7` になります。OSや他の拡張機能との競合があれば、同じ画面で変更してください。

global commandはChromeが起動中であれば、別アプリを操作しているときにも使えます。Chrome自体が完全に終了している場合、拡張機能のService Workerも動作していないため、このショートカットだけでChromeを起動することはできません。

## Macでの使い方

```text
Chromeを起動、または新しいタブを開く
→ 通常ウィンドウの未分類タブが灰色の tmp に入る
→ 既存グループ、ピン留め、シークレット、Chrome設定画面は触らない

Option + Shift + T
→ 現在のWebページを未処理専用ウィンドウへ送る
→ 専用グループを折りたたみ、元の作業ウィンドウへ戻る

Option + T
→ Chromeを前面に出す
→ 優先する未処理グループだけを専用ウィンドウで表示
→ 未処理グループを展開し、先頭タブを表示

Option + Shift + G
→ 現在のtmpタブ用の振り分けパレットを開く
→ プリセットは Control + 1〜9 で即決定
→ またはタイトルを検索し、既存グループを選ぶか新しい名前を入力してEnter
→ 選んだ名前の専用ウィンドウへ送る

Option + G
→ Chrome外からグループOverviewを開く
→ tmp、プリセット、現在開いている全グループ名とタブ数を一覧表示
→ タイトルを入力して絞り込み、Enterでそのグループへ移動
→ tmpは Control + 0、プリセットは Control + 1〜9 で即表示

終わったら ⌘W
→ 通常のChrome操作で対象タブを閉じる
```

4つのホットキーで、固定Inboxへの即送信・即表示と、TMPから任意グループへの振り分け・全体確認を完結できます。パレットではタイトル検索、上下キー、Enter、Esc、`Control + 0〜9` のクイック選択が使えます。新規グループの色は `Option + 1〜9` で選べるため、マウスは不要です。拡張機能アイコンのPopupは予備操作として残しており、4つの操作をボタンでも実行できます。

## TMPから振り分ける

`tmp` は保存先ではなく、判断前のタブを一時的に置く灰色のシステムグループです。

* 新しい通常タブ — デフォルトで、そのタブを開いたウィンドウ内の `tmp` へ入ります。
* Chrome起動時 — 各通常ウィンドウのアクティブタブだけを確認し、未グループなら `tmp` へ入れます。復元された全タブを一括移動しません。
* 既にグループ化済み、ピン留め、シークレット — 変更しません。
* 古い版などで同じウィンドウに `tmp` が複数残っている場合 — 拡張機能の起動・再読み込み時に1つへ統合します。所属タブは閉じません。
* `chrome://extensions`、設定、拡張機能ページ、`file:` — TMPへ入れません。
* TMPが1タブだけのウィンドウ — 操作中だけ空のプレースホルダーを作り、元タブそのものを安全に移動します。成功またはロールバック確認後にプレースホルダーを削除するため、コピーがTMPへ残り続けません。

自動TMP化、新規タブの対象化、Chrome起動時の対象化はOptionsで個別にOFFへ変更できます。OFFにしても既存の `tmp` タブを自動削除したり、別グループへ移したりしません。

## プリセットとグループOverview

Optionsの `Preset groups` で、よく使うグループを最大9件、名前・色・順番付きで保存できます。グループIDやウィンドウIDではなく名前を保存するため、空になってChromeから消えたグループも、次に振り分けると同じ名前と設定色で作り直せます。

`Option + G` のOverviewには次の順番で表示します。

1. システム `tmp`
2. 保存したプリセット（保存順、空なら0タブ）
3. 現在開いている未登録グループ

全行にタブ数を表示します。同じ正規化タイトルの物理グループが別ウィンドウにある場合も、Overviewでは1つの論理グループとして集約し、ウィンドウ数を表示します。検索欄は最初からフォーカスされるため、`Option + G → グループタイトルを数文字入力 → Enter` だけで目的のグループへ移動できます。検索対象は `tmp`、プリセット、現在開いている未登録グループのタイトルです。ページ内の個々のタブタイトルや閲覧履歴は検索対象にしません。

## 自由なグループを作る・入れる

`Option + Shift + G` を押すと、現在存在する名前付きChromeグループがタブ数付きで表示されます。

* 既存名を選んでEnter — 現在タブをそのグループへ送ります。
* 存在しない名前を入力してEnter — 選択中の色で新しいグループを作り、現在タブを入れます。
* 同じ名前のグループが同一ウィンドウに複数ある — 現在使っているグループを優先し、全所属タブをそこへ移して1グループに統合します。タブは閉じません。
* 同じ名前のグループが別ウィンドウにある — Chromeのグループはウィンドウをまたげないため物理的には別のままですが、Overviewでは1つとして扱い、最後に使ったウィンドウを優先します。
* 同じURLが選択したグループに既にある — 重複を作りません。
* 同じURLが別名のグループにある — 用途が異なるため、選択したグループにも入れられます。

グループ名は前後の空白を除いた1〜80文字で、大文字小文字を区別せず一意判定します。たとえば `Work`、`work`、` WORK ` は同じ名前です。Chromeの9色（グレー、ブルー、レッド、イエロー、グリーン、ピンク、パープル、シアン、オレンジ）から選べます。色チップは左から `Option + 1`〜`Option + 9` に対応します。プリセットとシステムグループは設定色を優先し、それ以外の既存グループは統合先の現在色を保持します。グループIDとウィンドウIDは保存せず、その時点のChrome状態から同じ名前を再発見します。空になったグループはChromeと一緒に消え、必要なら同じ名前をもう一度入力して作り直せます。

現在の作業ウィンドウに複数タブがある場合は、現在のタブだけを未処理専用ウィンドウへ移動し、近くの作業タブへ戻ります。現在の作業ウィンドウが1タブだけの場合は、そのウィンドウを壊さないため元のタブを残し、コピーを専用ウィンドウへ入れます。同じURLが既にInboxにある場合は新しいタブを作りません。

専用ウィンドウは、ウィンドウ内の全タブが1つの正規化タイトルのグループに所属しているかをChromeの現在状態から判定します。すでに清潔な専用ウィンドウがあれば再利用します。同じウィンドウ内の同名グループは自動統合しますが、別ウィンドウのグループ、別名グループ、関係のないタブは移動・削除しません。

専用ウィンドウで手動で通常の新規タブを開いた場合、その時点では「未処理だけ」の状態ではなくなります。次のホットキー実行時に新しい清潔な専用ウィンドウへ優先グループのタブだけを移し、手動で開いた通常タブは元のウィンドウ側へ残します。専用化の途中でChrome APIが失敗した場合も、既存のユーザータブを整理目的で削除しません。

Chromeは専用ウィンドウ内の最後の未処理タブを閉じると、そのウィンドウと空のタブグループを自動的に削除します。拡張機能は保持用のダミータブを作らず、次の追加時に専用ウィンドウとオレンジ色のグループを再作成します。保存直後は専用グループを折りたたみ、レビュー用ホットキーを押したときだけ展開します。

## iPhoneから追加する

### iPhone版Chrome

次の手順は、Google Chrome公式ヘルプの「[ページを後からオフラインで読む（iPhone / iPad）](https://support.google.com/chrome/answer/7343019?co=GENIE.Platform%3DiOS&hl=ja)」に基づきます。

1. iPhoneのChromeで、あとでやるページを開きます。
2. `…`（その他）メニューを開きます。
3. **「リーディング リストに追加」**（英語表示では `Add to Reading List`）を選びます。
4. iPhoneとMacのChromeを同じGoogleアカウントで使い、Reading ListをGoogleアカウントへ保存する設定を有効にします。Reading Listが同じアカウントで利用できることは「[すべてのデバイスで同じブックマーク、パスワード、その他の設定を利用する](https://support.google.com/chrome/answer/165139?hl=ja)」でも確認できます。
5. Mac Chromeへ同期されると、拡張機能が未読Reading Listを検出し、未処理専用ウィンドウのオレンジ色Inboxへバックグラウンドタブとして追加します。

### SafariやXなど、他のアプリ

1. ページの共有シートを開きます。
2. `Chrome` を選びます。
3. Chrome側で **「後で読む」** / Reading Listへの保存を選びます（表示名はiOSやChromeの版で異なる場合があります）。
4. 同じGoogleアカウントでログインしたMac Chromeへ同期されるのを待ちます。

Reading Listはこの拡張機能ではMacへ渡すための一時キューとして使います。`Queue behavior` の削除設定がONなら、タブ作成、グループ化、折りたたみ、バッジ更新、Inbox所属確認が成功した後にだけ元のReading List項目を削除します。Chrome APIの処理や削除が失敗した場合は項目を残し、次のスキャンで再試行します。

## Androidから追加する

Android版Chromeの現在の一般的な手順は、Chrome公式ヘルプの「[ページを後からオフラインで読む](https://support.google.com/chrome/answer/7343019?co=GENIE.Platform%3DAndroid&hl=ja)」に記載されているReading List保存方法に基づきます。

1. AndroidのChromeで対象ページを開きます。
2. アドレスバー右側の `⋮`（その他）をタップします。
3. スター（このページをブックマーク）をタップします。
4. 保存先の編集またはフォルダ選択を開き、**Reading List / リーディング リスト** を選びます。
5. AndroidとMacのChromeを同じGoogleアカウントで使い、Reading Listなどの同期を有効にします。
6. Mac Chromeへの同期後、拡張機能が未読項目を専用Inboxウィンドウへ取り込みます。

Android Chromeのメニュー名や配置は端末、Chromeの版、言語設定で変わることがあります。保存先が通常のブックマークになっていないことを確認してください。Androidの任意アプリから `共有 → まだやっていない` と直接送るShare Targetは将来機能であり、v1には含まれていません。比較とOS共通プロトコルの設計メモは [`docs/future-mobile-bridge.md`](docs/future-mobile-bridge.md) を参照してください。

## 初回セットアップと設定

初めて拡張機能が起動した時刻を `bridgeEnabledAt` としてChromeのローカル拡張ストレージへ保存します。自動処理は、未読かつReading List項目の `creationTime >= bridgeEnabledAt` のものだけを対象にします。これにより、インストール前から溜まっていた古い項目を勝手に大量投入しません。

既存の未読項目も取り込みたい場合は、Options画面の **「既存の未読Reading Listを取り込む」** を明示的に押してください。

Options画面の項目は次のとおりです。

* `新しいタブをtmpで受け取る` — デフォルトON。自動TMP化全体の主スイッチです。
* `新しく開いたタブをtmpへ` — デフォルトON。通常ウィンドウで新規作成された未分類タブだけを対象にします。
* `Chrome起動時のアクティブタブをtmpへ` — デフォルトON。各通常ウィンドウにつきアクティブな未分類タブ1件だけを対象にします。
* `Preset groups` — 最大9件。名前、Chromeの色、`Control + 1〜9` の順番を保存します。追加、削除、上下移動は明示的なボタン操作だけで行います。
* `Chrome Reading Listから取り込む` — デフォルトON。OFFの間は自動スキャンと追加イベントを処理しません。
* `既存の未読Reading Listを取り込む` — bridge開始時刻より前の項目も、押したときだけ処理します。
* `取り込み成功後Reading Listから削除` — デフォルトON。OFFならInboxへ成功してもReading List項目を残します。
* Reading Listの取り込み先 — `まだやっていない`、色はorangeで固定です。任意グループはデスクトップの選択パレットから作成します。

Chromeアカウントの同期には遅延があります。追加直後にMacへ現れなくても、数秒からさらに長い時間待ってください。イベントだけでなく、拡張機能の起動、Chrome起動、インストール/更新、一分間隔のalarmスキャンでも最終的な取りこぼしを補います。

## URLと重複の扱い

保存先グループへ振り分けられる対象は `http:` と `https:` のみです。`chrome://`、`chrome-extension://`、New Tab、`file:`、`data:`、`javascript:` などはクラッシュせず、Web Inbox項目として取り込みません。ただし、起動直後の `chrome://newtab` と `about:blank` は、これから行き先を決める一時タブとして `tmp` に入れられます。通常のWebページへ移動してから振り分けてください。Chrome Web Storeは `https:` のWebページなので通常はタブとして扱えますが、Chrome側が操作を拒否した場合もReading List項目を削除せず安全に停止します。

重複判定は、選択した名前と完全一致する全グループ内のURLとの完全一致です。クエリ文字列、フラグメント、パスを削りません。たとえば `?item=1` と `?item=2` は別URLとして扱います。同じURLが同じ名前のどこかのグループにあれば新しいタブを作りませんが、別名グループへの振り分けは許可します。

## トラブルシューティング

* **ショートカットが動かない** — `chrome://extensions/shortcuts` で未設定、他の拡張機能やOSショートカットとの競合、global欄ではなく通常欄に設定していないかを確認します。
* **OptionがAltと表示される** — Mac ChromeのショートカットUI上の表記差です。`Alt + T` は通常MacのOptionキーに対応します。
* **Inboxが増えない** — Popupの件数、OptionsのReading List ON/OFF、Reading Listが未読か、同じGoogleアカウントで同期しているか、対象URLがhttp(s)かを確認します。
* **古いReading Listが入らない** — 初回の安全動作です。Optionsで「既存の未読Reading Listを取り込む」を押してください。
* **Reading Listに項目が残る** — タブ/グループ処理または削除APIが失敗した可能性があります。データロス防止のため正常です。次のalarmスキャンで再試行します。既に同じURLのInboxタブがあれば、重複確認後に削除できる場合があります。
* **同じURLが増えたように見える** — URLのクエリ文字列やフラグメントが異なっていないか確認してください。完全に同じURLであれば、同じ名前のどのグループにあっても新しいタブを作りません。同一ウィンドウの同名グループは自動統合されます。
* **グループ選択パレットが出ない** — 拡張機能を再読み込みし、`chrome://extensions/shortcuts` で `choose-group-for-current` と `open-group-picker` が設定されているか確認してください。
* **新しいタブがtmpに入らない** — OptionsでTMP主スイッチと「新しく開いたタブ」がONか確認します。既に別グループ内、ピン留め、シークレット、Chrome設定ページは対象外です。
* **起動時に昔のタブが全部tmpへ入るのが心配** — 全タブは対象にしません。各通常ウィンドウのアクティブかつ未グループのタブだけです。必要なら起動時設定だけOFFにできます。
* **タイトル検索で見つからない** — 検索対象はグループタイトルです。個々のWebページのタブタイトルや閲覧履歴は検索しません。現在開いている名前付きグループか、Optionsで保存したプリセットか確認してください。
* **プリセットを選んでも開かない** — 0タブのプリセットは保存先としては使えますが、開く対象はまだありません。まずTMPタブをそのプリセットへ振り分けてください。
* **Chromeの再読み込み後に処理が再開しない** — `chrome://extensions` で再読み込みし、Reading Listに未読項目が残っている状態で一分程度待つか、Optionsの手動取り込みを使います。

## 手動確認手順（Chrome GUI）

以下はコード更新後に `chrome://extensions` で再読み込みして行う確認項目です。Nodeの自動テストはChrome GUI、実際のReading List同期、iPhone/Android端末での成功証拠にはならないため、分けて確認します。

1. 複数タブがある通常ウィンドウで `https://example.com/?case=one` を開き、add commandまたはPopupの「現在のタブを送る」を実行します。そのタブだけが別の専用ウィンドウへ移り、`まだやっていない` がorange・折りたたみ状態になり、元の作業ウィンドウへ戻ることを確認します。
2. 同じURLをもう一度追加します。専用ウィンドウ内のタブ数が増えず、Popupが重複を知らせることを確認します。
3. 別の通常タブを追加し、専用ウィンドウに未処理タブだけが2件入ることを確認します。通常の関係ないタブが一緒に移動していないことも確認します。
4. いったん別アプリへ移り、open commandを実行します。Chromeの専用ウィンドウが前面に出て、グループが展開され、最小indexのInboxタブがactiveになることを確認します。
5. タブを通常の `⌘W` で閉じ、バッジが現在のグループ内タブ数へ減ることを確認します。
6. Optionsで `研究`（blue）と `買うもの`（green）をプリセット登録し、保存後の順番と色が再読み込み後も保持されることを確認します。
7. 新しい通常タブを開き、灰色で展開された `tmp` に自動で入ることを確認します。既存グループ内タブ、ピン留めタブ、`chrome://extensions` はTMP化されないことも確認します。
8. TMPタブで振り分けパレットを開き、`Control + 1` だけで `研究` へ送れることを確認します。TMPが1タブだけのウィンドウでもコピーが残らず、元タブが `研究` 側へ移ることを確認します。
9. 同じURLを `研究` へもう一度送り、重複しないことを確認します。次に同じURLを別名 `読む` へ送り、別用途として追加できることを確認します。
10. Chrome以外のアプリから `Option + G` を押し、Overviewに `tmp`、0タブを含むプリセット、現在開いている未登録グループのタイトルとタブ数が一度に表示されることを確認します。
11. Overviewで `研` と入力し、`研究` だけに絞り込まれてEnterでその専用ウィンドウを表示できることを確認します。`Control + 0` でTMP、`Control + 1` で最初のプリセットも開けることを確認します。
12. テスト用プロファイルの同一ウィンドウで `Work` と ` work ` のグループを作ります。短時間後または拡張機能の再読み込み後に、全所属タブを保持したまま1グループへ統合されることを確認します。別ウィンドウにも同名を作った場合は物理グループを残しつつ、Overviewでは1件に集約されることを確認します。
13. ChromeのReading Listへ新しい未読 `https://example.com/?case=reading-list` を追加します。未処理専用ウィンドウへバックグラウンド追加され、削除設定ONなら成功後にReading Listから消えることを確認します。
14. タブ作成、専用ウィンドウ作成、移動、グループ処理のいずれかを失敗させた場合、Reading List項目が消えないことを確認します。故意にChrome状態を壊すテストは、重要な個人タブを避けた別プロファイルで行ってください。
15. 拡張機能を再読み込みし、未読Reading List項目が残っている状態でworker起動/一分alarmスキャンによって処理されることを確認します。
16. インストール前からある未読Reading List項目を用意してから初回インストールします。自動では入らず、Optionsの手動ボタン後にだけ入ることを確認します。
17. 1タブだけの通常グループから現在タブを送る場合は元の作業タブが残り、専用グループにはコピーが入ることを確認します。1タブだけのTMPから送る場合は、操作用プレースホルダーが片付けられ、元タブそのものが移動することを確認します。

Service Workerのログ確認は、`chrome://extensions` の対象拡張機能から「Service Worker」を開いてください。ログには `[inbox]`、`[reading-list]`、`[group]`、`[tab]`、`[queue]`、`[error]` の接頭辞が付きます。

## ローカル静的検証（任意テストを含む）

Node/npmは拡張機能に必要ありません。Nodeがインストールされている場合だけ、プロジェクトのルートで次を実行できます。

```sh
python3 -m json.tool manifest.json
find . -type f -name '*.js' -print0 | xargs -0 -n1 node --check
node --test tests/*.test.js
```

テストは外部依存なしで、URLのhttp(s)検証、クエリ/フラグメントを保持した完全一致、読み込み途中の`pendingUrl`重複、`bridgeEnabledAt`とTMP/プリセット設定の再起動後保持、プリセットの上限・大文字小文字を無視した重複・予約名検証、新規/起動タブのTMP適格性、1タブTMPのプレースホルダー移動、同一ウィンドウ内の正規化同名グループ統合、プリセット色優先、任意グループ色保持、別ウィンドウの保持、グループ名・色の検証、同名だけに限定したURL重複判定、専用ウィンドウの再利用と新規作成、別名グループと関係ないタブの保持、通常の1タブ作業ウィンドウのコピー保護、タブ/グループ処理失敗時のACK抑止、ウィンドウ状態の保持、Reading List削除失敗時の保持を確認します。これらはChrome GUIの成功を偽装するテストではありません。

## 実機・同期の境界

Codexのローカル作業だけでは、iPhone/Androidの共有シート、GoogleアカウントのReading List同期、Mac Chromeの実際のタブグループ挙動、ショートカットのOS競合を検証できません。上記の手動手順を、同じGoogleアカウントでログインした実機とMac Chromeで実行してください。特に次を確認します。

* iPhone Chrome、Safari、XなどからReading Listへ保存できること。
* Android Chromeで保存先をReading Listに選べること。
* Reading List同期が有効で、遅延後にMacへ届くこと。
* Mac拡張機能が未読項目だけを取り込み、成功後の削除だけを行うこと。
* 端末固有のUI名、OSショートカット、Chromeの同期設定がREADMEの表示と異ならないこと。
